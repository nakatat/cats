# 新サイト設計案

対象: 新琴似CATS 非公式公開サイト + 公開読み取り API
方針: 旧サイトは Before / 参考資料として扱い、新サイトでは公開体験を先に整える。
前提: まずは公開ページと公開 API を優先し、管理画面は後回し。お問い合わせフォームは作らない。

現時点では、公開Webと公開読み取りAPIが実装対象である。認証付きの管理画面、試合・成績の
入力API、複数チームを管理する機能は現実装には含まれない。以下では、実装済みの内容と
画面・機能の将来候補を分けて記載する。

## 1. 新サイトのコンセプト

新サイトは、草野球チームの活動と試合結果を気持ちよく追える公開サイトにする。

### 目指す見せ方

- チームの雰囲気が伝わる
- 直近の試合結果がすぐ分かる
- 選手の顔ぶれと役割が把握しやすい
- 打撃成績・投手成績を見やすく公開する
- スマホで閲覧しやすい
- 将来は複数チーム対応へ広げられる
- トップページは Deep Green の Hero とスコアボード風の成績表示を中心にする

### 旧サイトとの違い

- 旧サイトは管理機能と公開画面が同居していた
- 新サイトは公開サイト中心に分離する
- 旧サイトは一覧表中心だった
- 新サイトはトップのストーリー性、選手紹介、試合ハイライトを重視する

## 2. 公開ページ構成

### 現在実装しているWeb route

| Route | 役割 |
| --- | --- |
| `/` | チーム概要、直近・次回試合、成績概要、主要画面への導線 |
| `/games` | 試合一覧。年度・大会・結果などで絞り込む |
| `/games/[gameId]` | 試合詳細、参加者に紐づく打撃・投手成績、イニングスコア |
| `/players` | 選手一覧 |
| `/players/[playerId]` | 選手プロフィール、成績、直近試合 |
| `/stats` | 打撃成績、投手成績、ランキングをまとめて表示する |

チーム紹介、シーズン、大会の情報は、トップページや試合・成績画面の構成要素として
公開している。独立したWeb routeではない。

### 将来の画面候補

次のrouteは設計上の候補として残すが、現在のWeb実装には存在しない。

- `/team`（独立したチーム紹介）
- `/rankings`（ランキング専用画面）
- `/tournaments`（大会・リーグ情報専用画面）
- `/seasons/[year]`（シーズン専用画面）
- `/stats/batting`、`/stats/pitching`（成績の独立画面）

### 現在のページの役割

- `トップ`
  - Deep Green の Hero、チーム情報、直近・今後の試合、今季成績、主要ページへの導線を置く
- `試合一覧`
  - 年度・大会・結果・並び順で絞り込める一覧
- `試合詳細`
  - スコア、出場情報を含む打撃・投手成績、イニングスコアを見せる
- `選手一覧`
  - 顔写真、背番号、ポジション、投打、所属状況を見せる
- `選手詳細`
  - プロフィール、成績、直近出場を見せる
- `成績`
  - 打撃指標、投手指標、ランキングをシーズン単位または通算で表示する

### お問い合わせの扱い

- お問い合わせフォームは作らない
- 必要ならトップページやフッターに「練習試合・ご連絡は代表まで」とだけ置く

## 3. 画面 URL 設計

公開サイトとして読みやすく、将来の拡張にも耐えやすい URL にする。

### 現在実装しているWeb URL

- `/`
- `/games`
- `/games/[gameId]`
- `/players`
- `/players/[playerId]`
- `/stats`

### 将来候補のURL

- `/team`
- `/stats/batting`
- `/stats/pitching`
- `/rankings`
- `/tournaments`
- `/seasons/[year]`

画面URLにチームslugを含めず、表示対象チームはWebの `DEFAULT_TEAM_SLUG` で指定する。
APIは `/api/teams/{teamSlug}/...` を使用し、画面URLとAPI URLは分離する。

## 4. MVP の範囲

最初に作る範囲を明確にする。

### A. 現在実装済み

- チーム基本情報とトップページ向けサマリー
- 試合一覧、試合詳細、参加者、打撃・投手成績、イニングスコア
- 選手一覧、選手詳細
- `/stats` の打撃成績、投手成績、ランキング
- シーズン・大会を使った公開画面の絞り込み
- 公開読み取りAPI（認証なしのGET）

### B. 現在仕様として扱うが未実装

現時点でリポジトリから確定できるBの追加機能はない。独立画面や入力機能は、下記の
将来候補として扱う。

### C. 将来構想

- 独立したチーム紹介、大会、ランキング、シーズン、成績画面
- ログイン、管理画面、権限管理、試合・成績の入力
- 複数チーム登録、課金、招待
- LINE連携、メール送信、写真ギャラリー
- 打席単位入力、守備詳細、イニング別イベント入力

お問い合わせフォームは作らない方針であり、現時点では将来候補にも含めない。

## 5. フロントエンド設計方針

フロントは公開サイトとして見て楽しいことを優先し、管理画面っぽくしすぎない。

### デザイン方針

- Deep Green を基調にする
- Gold はアクセントとして少量だけ使う
- Hero は濃いグリーンで締める
- 角丸は大きすぎないようにする
- カードは影より border と余白で整える
- スコアや戦績が主役に見えるようにする
- スマホでも見やすいレスポンシブにする

### トップページの構成

- Hero
  - チーム名、英字表記、活動地域、説明文、現在シーズンをまとめる
- Season Record
  - 試合数、勝ち、負け、引き分け、勝率、得点、失点を大きく見せる
- Recent Games
  - スコアボード風に直近の試合結果を見せる
- Upcoming Games
  - 次の予定が分かる見た目にする
- Navigation Cards
  - 試合一覧、選手一覧、打撃成績、投手成績、ランキングへの導線を置く

### 実装の考え方

- 画面と公開APIの責務を分け、画面はAPIを読む前提で作る
- タブレットとスマホでも情報の優先順位が崩れないようにする
- API呼び出し、共通UI、コンポーネント分割の実装ルールは
  [フロントエンド UI 方針](frontend-ui-guidelines.md) と現在の実装を正とする
